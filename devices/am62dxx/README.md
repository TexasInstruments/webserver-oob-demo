# AM62D WebServer Out-of-Box Demo

This directory contains the AM62D device configuration, native utilities,
Vue/Vuetify device views, demo components, board assets, and the AM62D user
and developer documentation for the WebServer Out-of-Box Demo.

The AM62D portal runs in a browser connected to the webserver on the EVM. The
browser UI is built with Vue 3, Vuetify, Vue Router, and Vite. The Node.js
server remains responsible for REST/WebSocket APIs and for launching the demo
backends on the EVM.

## Current AM62D repository structure

```text
devices/am62dxx/
├── device.json                 Device identity, demos, paths, and public docs
├── docs/
│   ├── am62d-user-guide.html
│   └── am62d-developer-guide.html
├── ui/
│   ├── index.js                AM62D routes, navigation, demos, and guide URLs
│   ├── views/                  Audio DSP, DSP compute, and model inspector views
│   └── demos/                  AM62D demo components
├── app/                        Board assets and generated frontend deployment tree
│   ├── images/
│   ├── Model-Inspector/
│   └── vue-dist/               Generated by the Vite build
└── linux_app/                  AM62D native helper build files
```

Shared code is located elsewhere in the repository:

```text
frontend/src/                   Shared Vue application and reusable components
common/webserver/               Node.js/Express server and WebSocket server
demos/                          Demo backend plugins and manifests
common/linux_app/               Shared native utilities
Makefile                        Build and deployment orchestration
```

## Portal architecture

```text
Browser
  └─ Vue/Vuetify portal
       ├─ frontend/src/                 Shared shell, router, and components
       └─ devices/am62dxx/ui/           AM62D views and demo components
             └─ packaged by Vite into devices/am62dxx/app/vue-dist/
                    └─ served by common/webserver/server.js
                         ├─ REST APIs
                         ├─ WebSocket APIs
                         └─ demos/<id>/server-plugin.js
                              └─ AM62D native applications / RPMsg-DMA / GStreamer
```

`devices/am62dxx/device.json` selects the Vue UI and controls the active demo
plugins. The current AM62D demo set is:

- Audio Classification
- Speech Enhancement
- Audio DSP Offload
- 2D FFT
- Sigchain Biquad
- Custom GStreamer Pipeline
- AI Model Inspector (frontend tool)

## Prerequisites

For frontend development, use Node.js 20 or newer and npm. The EVM does not
need the frontend build tools; it only needs the generated static files and
the webserver runtime.

The AM62D image must also contain the native Edge-AI/RPMsg-DMA artifacts used
by the configured demos. Typical paths are:

```text
/usr/bin/rpmsg_inference_example
/usr/bin/rpmsg_audio_offload_example
/usr/bin/rpmsg_2dfft_example
/usr/bin/rpmsg_sigchain_biquad_example
/usr/share/tvm_inference/json/
/usr/share/tvm_inference/artifacts/
/usr/share/tvm_inference/input/input_audio.wav
```

The WebServer repository does not build or install the RPMsg-DMA applications
or their model artifacts. Build and install those separately before running
the corresponding demos.

## Local development

Install the shared server dependencies and build the AM62D portal:

```bash
cd common/webserver
npm install
cd ../..

make build-frontend DEVICE=am62dxx
```

Run the complete server locally with mocked backend data:

```bash
make dev DEVICE=am62dxx MOCK=1
```

Open `http://localhost:3000`. The server uses the AM62D device configuration
and serves the generated Vue application when
`devices/am62dxx/app/vue-dist/index.html` exists.

For frontend-only iteration, run the Vite development server in another
terminal:

```bash
cd frontend
npm install
VITE_DEVICE=am62dxx npm run dev
```

The Vite development server runs on port 5173 and proxies demo API and
WebSocket requests to the Node.js server on port 3000.

## Build

Build the native helpers and the AM62D frontend from the repository root:

```bash
make build DEVICE=am62dxx
```

Build only the Vue/Vuetify portal:

```bash
make build-frontend DEVICE=am62dxx
```

The frontend output is written to:

```text
devices/am62dxx/app/vue-dist/
```

The Vite build uses `/vue-dist/` as its base path. Do not open the generated
`index.html` directly from the filesystem; serve it through the webserver or
the Vite preview server.

There is currently no `npm test`, `make push`, or `make find-board` target in
the repository Makefile. Use the commands listed here and inspect the
Makefile when adding new automation.

## Deploy to an EVM

Deploy the complete AM62D application to a reachable board:

```bash
make deploy DEVICE=am62dxx BOARD_HOST=root@<EVM_IP>
```

This performs the following operations:

1. Builds the native helpers and AM62D frontend.
2. Copies available native helper binaries to `/usr/bin/`.
3. Installs the Node.js server and demo plugins under
   `/usr/share/webserver-oob/`.
4. Replaces the board application directory with the shared app, AM62D app
   assets, generated `vue-dist/`, and `device.json`.

Restart the service after deployment:

```bash
make deploy-restart BOARD_HOST=root@<EVM_IP>
```

The service can also be restarted directly:

```bash
ssh root@<EVM_IP> "systemctl restart webserver-oob"
```

## Runtime file locations

| Item | EVM path |
|---|---|
| Vue portal and packaged guides | `/usr/share/webserver-oob/app/vue-dist/` |
| Board images and model-inspector assets | `/usr/share/webserver-oob/app/` |
| Device configuration | `/usr/share/webserver-oob/app/device.json` |
| Node.js server (manual deployment) | `/usr/share/webserver-oob/server/` |
| Demo plugins | `/usr/share/webserver-oob/demos/<demo>/` |
| Server configuration | `/etc/webserver-oob.conf` |
| Native helper binaries | `/usr/bin/` |
| Service unit | `webserver-oob.service` (packaged service normally runs `/usr/lib/node_modules/webserver-oob/server.js`) |

The server chooses the Vue entry point from
`<device-app>/vue-dist/index.html` when `device.json` contains
`"ui": "vue"`. It still serves the shared legacy app tree for devices that
do not use the Vue portal.

## Documentation assets and navigation

The AM62D navigation is defined in `devices/am62dxx/ui/index.js`:

| Navigation entry | Behavior |
|---|---|
| User Guide | Opens the packaged local `am62d-user-guide.html` in a new tab |
| Developer Guide | Opens the packaged local `am62d-developer-guide.html` in a new tab |
| SDK Documentation | Opens the public TI Processor SDK documentation in a new tab |

The guide imports use Vite URL imports. This is important: the generated
asset URL must be used instead of a GitHub URL inside the EVM portal, so the
guides remain available without internet access.

## Device configuration

`devices/am62dxx/device.json` is the source of truth for the AM62D runtime
configuration. It defines:

- the device ID, display name, board description, and SoC information;
- the Vue UI selection (`"ui": "vue"`);
- the active demo plugin IDs;
- device-specific binary, model, input, and socket paths; and
- public documentation cards shown by the portal.

When adding or renaming a demo, update all of the following consistently:

1. `device.json` under `demos` and, when needed, `demoConfig`;
2. the matching directory under `demos/`;
3. its `manifest.json` and `server-plugin.js`;
4. the AM62D frontend navigation or demo view under `devices/am62dxx/ui/`;
5. the User and Developer Guides when the user-visible behavior changes.

## Backend plugin contract

Each active demo plugin exports a registration function:

```js
module.exports = function register(app, wss, device) {
  // Register REST routes and WebSocket handlers.
};
```

Plugins should:

- honor `MOCK=1` so the portal can run on a development host;
- read device-specific paths from `device.demoConfig` rather than hardcoding
  them in the plugin;
- clean up child processes on stop, cancellation, `SIGTERM`, and `SIGINT`;
- validate user-provided paths and parameters before launching native tools;
- return clear HTTP errors and useful server log messages; and
- avoid leaving DSP ownership, sockets, temporary files, or child processes
  active after a demo ends.

The server exposes common endpoints including `/ping`, `/version`,
`/device-info`, `/demo-manifests`, and `/logs`. Demo-specific REST and
WebSocket endpoints are documented in the AM62D Developer Guide.

## Adding or changing a frontend feature

Shared shell behavior belongs in `frontend/src/`. AM62D-only behavior belongs
in `devices/am62dxx/ui/`. Use the existing router, Vuetify components, and
shared composables where possible. Keep API calls and WebSocket cleanup tied
to the component lifecycle so navigating between demos cannot leave a running
session behind.

For a new AM62D static asset, place board-specific files under
`devices/am62dxx/app/`. For a new documentation page that must be available
inside the EVM portal, place the HTML file under `devices/am62dxx/docs/`,
import it with Vite's `?url` syntax in `devices/am62dxx/ui/index.js`, and add a
new-tab Documentation navigation item.

## Troubleshooting

### Portal opens the legacy page

Rebuild the AM62D frontend and verify that this file exists:

```text
devices/am62dxx/app/vue-dist/index.html
```

On the EVM, verify the corresponding file exists under
`/usr/share/webserver-oob/app/vue-dist/` and restart the service.

### Guide link downloads or opens a GitHub page

Check that the navigation item uses the Vite-imported local URL from
`devices/am62dxx/ui/index.js` and has `target: '_blank'`. Rebuild and redeploy
the frontend; do not replace the local URL with a GitHub URL in the EVM UI.

### Demo reports a missing binary or model

Compare the paths in `devices/am62dxx/device.json` with the files installed on
the EVM. The webserver build does not install RPMsg-DMA binaries, firmware,
or model artifacts.

### Inspect service logs

```bash
ssh root@<EVM_IP> "systemctl status webserver-oob"
ssh root@<EVM_IP> "journalctl -u webserver-oob -f"
```
